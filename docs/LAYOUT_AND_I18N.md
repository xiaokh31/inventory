# 库位布局与多语言管理

更新：2026-10-03。

## 19 列的计算

按“最右柱垂直方向为第 1 列，向左第二根柱垂直方向为第 10 列”计数，两柱中心之间是 9 个间隔。ABC 各跨两段柱距，因此各为 19 列，共 57 列、114 个半区。

原图柱中心横坐标为 1012、811、610，每跨 201 像素，列中心间距为 `201 / 9 = 22.333…` 图纸像素。01、10、19 的中心分别落在三根柱上，最外列边缘各超出端柱中心半个间隔。柱位、办公室、叉车道和原图保持原坐标。

本次不重新推算柱距的实际米数。纵向托盘示意沿用原尺度；容量仍为示意，需要现场核对。

## 已有库存的兼容方式

不执行数据库迁移、批量更新或导入。没有 `layoutVersion` 或其值为 1 的记录继续使用冻结的原 15 列坐标；新记录写入 `layoutVersion: 2`，使用 19 列网格。所有记录的 `location` 都属于自身布局版本。

页面使用 `recordLaneId()` 把旧货物的横向中心对应到最近的新列中心，显示新列号；实际旧托盘图形仍由原坐标绘制。详情保留原编号，搜索同时支持新旧编号。统计按当前新列汇总，数量不会因图形容量而减少。

| 原编号后缀 | 当前列号后缀 |
| --- | --- |
| 01 / 02 / 03 / 04 / 05 | 02 / 03 / 04 / 05 / 06 |
| 06 / 07 / 08 / 09 / 10 | 08 / 09 / 10 / 11 / 12 |
| 11 / 12 / 13 / 14 / 15 | 14 / 15 / 16 / 17 / 18 |

表格适用于 A/B/C。对应新号只用于界面，不回写原始记录。编辑旧货物的信息或半区会保留横向坐标；只有用户选择其他新纵列时才转换到布局 2。新货物的示意格会避开现有旧货物图形。

JSON 备份版本升为 5，可混合保存两种布局并恢复原位置。旧 v1/v2 备份先按原规则反转编号，v3/v4 不反转，均按旧布局解释。含布局 2 的记录不可标为旧备份版本。CSV 是只读报表，含当前列号、原编号、布局版本和半区。

写入 API 必须提供 `clientLayoutVersion: 2`。旧页面的写入在事务之前返回 400 和 `LAYOUT_UPDATED`，提示刷新，避免旧页面把新网格记录写成旧网格记录。此处不使用 409，以免旧界面把刷新提示替换为普通并发冲突提示。GET 不改写数据；正常的记录版本和全仓修订号冲突保护继续使用。升级后各设备刷新一次即可。

不要直接回滚到不认识布局 2 的旧服务器版本；有新网格记录后，回滚版本也必须保留上述读写兼容逻辑。

## 中英文管理

参考只读项目 `stripSystem` 的提交 `1608420b6f5cd160624012b105cb5069261aa569`，对应文件为 `apps/web/src/lib/i18n/{catalog,translator,browser}.ts` 及 `components/i18n/{i18n-provider,language-switcher}.tsx`。本项目沿用集中词典、插值、浏览器语言偏好、即时切换和保持草稿的行为，适配为无框架 HTML，不引入其 React 或业务模块。

- `src/locales/zh-CN.json`、`src/locales/en.json`：同一组文案键，中英文集中维护。文案键使用现有中文源文，动态值使用 `{0}` 等占位符。
- `src/i18n.js`：`t(key, params)` 提供显式翻译；`ui` 标签模板仅翻译源码中的文案，最后再插入货物名称、柜号等数据，业务原文不参与词典匹配。静态模板只在启动时绑定原始文本节点和可访问性属性，不观察或翻译动态业务内容。
- 页面顶栏显示中文 / English；编辑表单内也有语言选择。切换不刷新页面，不重置草稿、筛选、视图或地图旋转。数字和日期采用当前语言，业务日期时区仍为 Asia/Shanghai。
- 偏好优先读取 `bestar_locale` Cookie，再读取 `bestar.locale` 本地偏好；首次访问跟随浏览器，中文语言归一为 zh-CN，其他语言回退 English。Cookie 按当前站点存储一年，HTTPS 下设置 Secure；不写库存数据库。
- `src/errors.cjs` 根据请求的 Accept-Language 翻译服务端错误；每个请求独立处理，避免影响其他用户的语言。

新增或修改文案时同步更新两份词典，并保持占位符一致。界面 HTML 的插值序号变化也应同步更新对应词条。词典缺失会在检查时失败，不静默显示未翻译键。`scripts/build.cjs` 内嵌两份词典，Docker/Vercel 使用相同构建产物。

## 验证

通过 Docker 运行 `docker compose --env-file .env.docker --profile test run --build --rm test`。包含 25 项模型/多语言/构建检查、6 项真实 PostgreSQL API 检查和应用 HTTP 检查。

`tests/legacy-layout-v1.json` 从部署前提交 `47056e9` 冻结，不含库存业务数据，用于核对原 45 列每个半区的全部托盘坐标。测试也覆盖混合布局备份、旧记录编辑、旧客户端阻断及新 C-19 入库。接口测试使用唯一临时记录并自行删除；数据库测试使用随机隔离 schema 并在结束时删除。

生产验证只读取库存和健康状态，对比发布前后的内容摘要、修订号及原托盘坐标，不复制业务数据到本机数据库，也不在生产写测试货物。
