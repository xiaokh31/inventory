## 19 列的计算

按“最右柱垂直方向为第 1 列，向左第二根柱垂直方向为第 10 列”计数，两柱中心之间是 9 个间隔。ABC 各跨两段柱距，因此各为 19 列，共 57 列、114 个半区。

原图柱中心横坐标为 1012、811、610，每跨 201 像素，列中心间距为 `201 / 9 = 22.333…` 图纸像素。01、10、19 的中心分别落在三根柱上，最外列边缘各超出端柱中心半个间隔。柱位、办公室、叉车道和原图保持原坐标。

本次不重新推算柱距的实际米数。纵向托盘示意沿用原尺度；容量仍为示意，需要现场核对。

## 已有库存的定位规则（错位修复）

数据库的 `location` 是现场登记的库位编号，必须作为定位依据。例如原记录 A-01 对齐当前 A-01，C-15 对齐当前 C-15，上下半区不变。无论 `layoutVersion` 缺省、为 1 或为 2，所有托盘都由当前 19 列网格绘制；同一编号的新旧记录共享同一组托盘示意格。

此前使用“冻结旧坐标并映射到最近的新列”的做法是错误的：A-01 被显示为 A-02，托盘没有对齐新网格。该逻辑已移除。地图图形、点击、台账、搜索、编辑、统计和 CSV 全部使用原登记编号，不再转换到附近的其他列。

修复不需要数据库迁移、批量更新或重新导入。保留所有记录的 ID、库位、半区、数量、业务字段、更新时间及并发版本；仅更新库位编号对应的绘制坐标。仅编辑信息或半区会保留原编号及记录格式，选择其他列时才写入所选编号和 `layoutVersion: 2`。

`LEGACY_LANES` 仅用于旧记录编号范围验证及早期备份兼容检查，不参与货物绘制。`palletFigures()` 统一在 `LANES` 中分配位置，图形中心与该编号的网格中心重合，并避开柱位。同列同半区的新旧批次不会重叠。超过示意容量的实际数量继续完整保留。

JSON 备份版本为 5，保留各记录的原始布局标记。旧 v1/v2 备份先按历史规则反转编号，v3/v4/v5 不反转；最终都按转换后的库位编号绘制到当前网格。含布局 2 的记录不可标为旧备份版本。CSV 保留现有列结构，其中当前列号与登记原编号一致。

写入 API 必须提供 `clientLayoutVersion: 3`，它是客户端定位协议版本，与记录的 `layoutVersion` 分开。此前使用错误映射的版本 2 页面及更旧页面均在写入事务前返回 400 和 `LAYOUT_UPDATED`，提示刷新。此处不使用 409，以免旧界面把刷新提示替换为普通并发冲突提示。GET 不改写数据；正常的并发冲突保护继续使用。升级后各设备刷新一次即可。

不要回滚到冻结旧坐标或不认识布局 2 记录的服务器版本。回滚也必须保留原编号定位和客户端协议版本 3 的检查。

## 中英文管理

参考只读项目 `stripSystem` 的提交 `1608420b6f5cd160624012b105cb5069261aa569`，对应文件为 `apps/web/src/lib/i18n/{catalog,translator,browser}.ts` 及 `components/i18n/{i18n-provider,language-switcher}.tsx`。本项目沿用集中词典、插值、浏览器语言偏好、即时切换和保持草稿的行为，适配为无框架 HTML，不引入其 React 或业务模块。

- `src/locales/zh-CN.json`、`src/locales/en.json`：同一组文案键，中英文集中维护。文案键使用现有中文源文，动态值使用 `{0}` 等占位符。
- `src/i18n.js`：`t(key, params)` 提供显式翻译；`ui` 标签模板仅翻译源码中的文案，最后再插入货物名称、柜号等数据，业务原文不参与词典匹配。静态模板只在启动时绑定原始文本节点和可访问性属性，不观察或翻译动态业务内容。
- 页面顶栏显示中文 / English；编辑表单内也有语言选择。切换不刷新页面，不重置草稿、筛选、视图或地图旋转。数字和日期采用当前语言，业务日期时区仍为 Asia/Shanghai。
- 偏好优先读取 `bestar_locale` Cookie，再读取 `bestar.locale` 本地偏好；首次访问跟随浏览器，中文语言归一为 zh-CN，其他语言回退 English。Cookie 按当前站点存储一年，HTTPS 下设置 Secure；不写库存数据库。
- `src/errors.cjs` 根据请求的 Accept-Language 翻译服务端错误；每个请求独立处理，避免影响其他用户的语言。

新增或修改文案时同步更新两份词典，并保持占位符一致。界面 HTML 的插值序号变化也应同步更新对应词条。词典缺失会在检查时失败，不静默显示未翻译键。`scripts/build.cjs` 内嵌两份词典，Docker/Vercel 使用相同构建产物。

## 验证

通过 Docker 运行 `docker compose --env-file .env.docker --profile test run --build --rm test`。包含 26 项模型/多语言/构建检查、6 项真实 PostgreSQL API 检查和应用 HTTP 检查。

回归检查覆盖原 45 列及上下半区：原编号不变，全部托盘与对应的当前网格对齐，各记录版本显示一致。测试也覆盖同列新旧批次分配、备份往返、旧记录编辑、协议版本 2 的新增/删除/导入阻断及新 C-19 入库。接口测试使用唯一临时记录并自行删除；数据库测试使用随机隔离 schema 并在结束时删除。

生产验证只读取库存和健康状态，对比发布前后的内容摘要、修订号及原登记编号；在浏览器核对每个托盘与对应网格中心的偏差为零。不复制业务数据到本机数据库，也不在生产写测试货物。
